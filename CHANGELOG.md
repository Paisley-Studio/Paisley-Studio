# Attendance: subsections, tutor attendance, strike reset policy, optional facial recognition (2026-11-11)

- **Admin > Attendance has seven subsections** (still one Attendance nav item): Overview (today's lessons, expected / checked in / present / late / absent / unresolved, tutors confirmed, reports awaiting submission, auto-submitted reports, students at 3+ strikes), Student attendance, Tutor attendance, Records and history (reviews, requests, follow-ups, failed emails, the audit trail), Strikes and disciplinary (strikes in the dates, final warnings, referrals), Facial recognition, Settings. The chosen subsection is remembered per browser.
- **Tutor attendance.** The rollcall shows "Confirm you are teaching this lesson": I'm teaching (`attendanceTutorCheckIn`), or face verification where enabled. Stored once as `attendanceSessions.tutorPresence.{tutorId}` (server time, on time / late, method); a later face match only adds `faceVerifiedAt`. Shown in the admin Overview and Tutor attendance.
- **Check-in method.** Registrations carry `checkIn.method` (`online` or `face`), shown in the tutor register (new Method column), the admin register and the student / parent history, and kept in the submitted snapshot (`checkInMethod`).
- **Strike reset policy** (Admin > Attendance > Settings, `attendanceSettings/policy`): every academic year (default, start month configurable), every calendar year, never, or only when the Studio Desk resets. Changing it recounts `attendanceStudents` counters from the strikes (none deleted); manual resets start a new counting period. Notices and emails say "this academic year" / "this calendar year" / "since <date>" to match. Counter keys stay `y2026` for the default, so existing data needs no migration.
- **Facial recognition (optional, off by default).** Admin > Attendance > Facial recognition: enable / suspend / disable (reason required, audited, engine health-checked before enabling), engine connection (CompreFace URL + API key, stored in `privateConfig`, never sent to a browser), confidence threshold, margin and log retention, student-processing approval (needs a DPIA reference and safeguards confirmation), student and tutor profiles (search, record / withdraw consent, upload / replace reference photo, remove enrollment, status), profiles needing attention, recognition activity and change log. Students and tutors see a face option only when `attendanceToday` says `recognition.available` (switch enabled, students approved, enrolled, consent granted); otherwise no button, no camera request. Face check-in uses the same `checkIn` engine (server time, one record, one strike). A match must be exactly one face, the caller's own subject (`s_<uid>` / `t_<uid>`), at or above the threshold and clear of any other subject by the margin; everything else is refused and logged. Engine down or switched off: the normal check-in. Parents give or withdraw consent for their child in the Parent Portal; tutors can withdraw theirs; withdrawal deletes the engine's face data. `faceRetention` (daily) prunes attempt logs, retries deletions and flags inactive accounts. `functions/face-recognition.js`, `functions/face-provider.js`, `js/attendance/face.js`; see `ATTENDANCE_RECOGNITION.md`.
- Tests: `functions/test/face.emulator.test.js`, recognition rules in `tests/rules/attendance.rules.test.js`.
- Deploy: functions (`faceAdmin`, `faceCheckIn`, `faceTutorVerify`, `faceConsent`, `faceRetention`, `attendanceTutorCheckIn`, changed attendance functions), then firestore rules + hosting. Recognition stays disabled until the Studio Desk enables it.

# Paisley VS Code: linking that just works, link suggestions, renaming, coloured icons; emoji in chats (2026-11-10)

- **Linked files work in the preview, live.** The preview follows the code a moment after each change (Run still restarts it from scratch). A `<link>` or `<script src>` finds its file even with a different capital letter, or when the file sits in another folder and is the only one with that name. A script linked in `<head>` waits for the page (like `defer`, loaded from a data: link), so `document.getElementById` finds the page instead of `null`, which is why scripts did nothing before. A link to a file that does not exist prints a warning in the Console. Re-rendering the same page no longer empties the Console.
- **Link suggestions.** In an HTML file, typing `link`, `css` or a style file name offers `<link rel="stylesheet" href="…">` for each of the project's own CSS files with the right path from that page; `script`/`js` does the same for JS files, `a` for other pages and `img`/`video`/`audio` for uploads. Enter writes the tag. Inside `href=""`, `src=""` and CSS `url(` the project's real paths are offered. Making a new CSS/JS file (or a new page) shows a bar: "Link style.css to index.html?" and Link it puts the tag before `</head>` (styles) or `</body>` (scripts).
- **Rename files, folders and uploads.** Pencil buttons in the tree, or double-click. A name with no ending keeps the old one. Every link in the project's HTML, CSS and JS that pointed at the old path is rewritten (`relink`), including links from pages that moved with a renamed folder.
- **Icons in their usual colours:** HTML orange-red, CSS blue, JavaScript yellow.
- **Emoji in every message box** (`js/ui/emoji-picker.js`, loaded on every portal dashboard). A smiley button beside each chat, message, reply or comment box opens a WhatsApp-style picker (search, categories, recents, skin tones; the `emoji-picker-element` component from jsDelivr, with a built-in grid if it cannot load). It finds boxes by placeholder or `data-emoji`, including ones drawn later; `data-emoji="off"` opts out. Emoji are only for what people type; the site's own UI still uses Font Awesome icons.

# Attendance, rollcall and punctuality; renaming subjects (2026-11-06)

- **Lessons come from the timetable.** Each `timetableEntries` session (weekly day + start/end, Key Stage, subject, board, optional tutor) becomes a register `attendanceSessions/{entryId}_{date}` 20 minutes before it starts, with one `attendanceRecords/{session}_{student}` per enrolled student: online students who are Active, take the subject (or have none saved) and follow the board. The tutor is the named one, else every tutor who covers that Key Stage + subject + board. All times are Africa/Nairobi. `attendanceSweep` (every 5 minutes) prepares registers so they exist even if nobody opens a page; `attendanceToday` prepares them on demand.
- **Students.** A get-ready banner 15 minutes before; at the start a registration pop-up ("I'm Here: Register Attendance") that can be minimised but not dismissed, comes back when the student returns, and holds lesson links and the Classroom until they register (account, results and help stay open). `attendanceCheckIn` stamps the server time: 15:00 or more after the start is late (14:59 is on time). Registration opens 10 minutes early and closes at the end of the lesson. Duplicate or retried registrations return the first one. A registration after the tutor submitted is kept and shown to the tutor to verify ("Awaiting tutor verification"). My attendance is on the Overview.
- **Tutors.** The rollcall pop-up opens by itself at the start of each lesson, updates live and can be closed: registrations keep arriving, a Rollcall button stays on screen, and a closed register does not pop up again. Attendance tab: today's registers, follow-ups, submission history. Nobody is marked absent automatically: after the grace period unregistered students are flagged "unaccounted for" and the tutor records Absent, Present but unable to check in, Connectivity / device issue, Excused by administration or Other (reason required), with their name and the time. Excused and Other go to the Studio Desk for review. Submitting needs every student accounted for.
- **Auto-submit.** A register not submitted 15 minutes after the lesson ends (`AUTO_SUBMIT_AFTER_END_MIN`) is submitted by the sweep as AUTO-SUBMITTED: registrations and their times are kept, unaccounted students stay unresolved (never absent), `manualSubmission: false`, the Studio Desk is emailed and the tutor asked for an explanation. Later follow-ups go to `attendanceAmendments`; the snapshot `attendanceSubmissions/{session}` never changes.
- **Subject lock.** From the end of the lesson until the register is in, `attendanceLocks/{tutor}_{subject}` pauses marking and paper hand-ins in that subject (rules `attendanceLocked`, and `tutorReleaseWork`). Other subjects and all teaching materials stay open; the Studio Desk can override it with a reason.
- **Strikes.** Every late registration is one strike (`attendanceStrikes/{recordId}`, so one per lesson), counted per academic year (September to August, `attendanceStudents.years.y2026`) across all subjects, in the same transaction as the registration. 4th: formal warning to the student and parent. 5th and later: `attendanceReferrals`, the Studio Desk and the parent are told. No automatic punishment. Reversal is admin-only, needs a reason, and keeps the strike as reversed.
- **Notices.** Late arrival (immediately), absence (when the register is submitted, or a later confirmed follow-up), warnings, referrals and auto-submits are saved in `attendanceNotifications` (deterministic ids) with email state pending / sent / failed; failed emails retry up to 5 times; each notice is also a bell. Parents see them, with delivery, in the Parent Portal's new Attendance section.
- **Studio Desk: Admin > Attendance.** Daily attendance, tutor compliance (manual vs auto-submitted, outstanding, explanations, locks), student punctuality (percentages, strikes, warnings, referrals, full record), reviews (tutor explanations, correction and excused-lateness requests, auto-submitted and unresolved registers, referrals) and failed emails; filters by date, subject, class, tutor, student and status. Every decision needs a reason and is written to `attendanceAudit`; corrections keep the original registration and append to `corrections`.
- **Rename subjects.** Admin > Key Stages & Fees > Subject names. `renameSubject` saves the name in `lmsSettings/subjects` (applied on every page by `lmzApplySubjectNames` in lms-helpers.js; the old name stays as an alias) and rewrites stored `subjectName` / `subjectNames` on timetables, classrooms and their work, resources, student and tutor profiles and open registers. Subject ids never change.
- Tests: `functions/test/attendance.emulator.test.js` (Firestore emulator) and `tests/rules/attendance.rules.test.js`.

## Deviations you should know about

1. **AI exam attempts stay in top-level `examAttempts`.** `student/exam.html` and the `recordViolation` callable are bound to `exams/{id}` and `examAttempts`. Re-nesting them means editing the integrity code you told me not to touch. Instead, a nested AI exam keeps a `legacyExamId` pointer and a mirror doc is written to `exams/{legacyExamId}`. `exam.html` is unchanged. Only PDF-mode attempts use `topics/{tid}/exams/{eid}/attempts/{uid}`.
2. **Recipient scoping for tutors is enforced after the fact.** Firestore rules cannot loop over a list and check each student. The client only offers enrolled students, and `onAssignmentPosted` removes anyone not enrolled (and deletes the assignment if nobody valid is left).
3. **Parents are blocked from homework PDFs in the UI only.** Parents can read the assignment document (needed for the status view), which contains `attachedPdfUrl`. Storage `get` has always been open to any signed-in user via unguessable tokens. Truly blocking it needs the PDF URL moved into a student-only subdocument.
4. **Graded file name** is `graded_{studentName}_{assignmentTitle}.pdf` (section 5). Section "STUDENT" asked for "graded + original PDF name"; the two conflict and I chose section 5.
5. **Tickets and Messages nav badges** keep their existing live counters. The new bell-driven badges are on Classroom, Homework, Exams and Notices.
6. **Tutors can still update legacy top-level homework/exams they own**; only creation is revoked.
7. **Ink storage limit.** Ink is stored on the submission document (1 MiB Firestore cap). Points are thinned and a 900 KB guard stops syncing with a visible warning. Marks are also mirrored to the browser's localStorage and restored on reopen.
